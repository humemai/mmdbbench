# Checks and audit tools

The tools in this directory read result rows or rep-state files and say what is missing or wrong before the rows are landed. The gates that run inside the landing (the `*_check.py` files of `experiments/`, see [PUBLISHING.md](../PUBLISHING.md)) are separate. Each tool has a test in this directory that runs in the harness tests of the repository (`.github/workflows/test-experiments.yml`), with no Docker, no data and no benchmark host. A new, changed or removed tool edits its row here in the same change.

| Tool | What it catches | When | Test | What to do with the result |
| --- | --- | --- | --- | --- |
| [merge_fourarm_rows.py](merge_fourarm_rows.py) | `land_stage.py` pulls one rows file from one directory of the bench host, but the four-arm rows live in four places (the live and the catch-up worktrees, JVM and native). It builds the one file, one row per `(engine_backend, run_id)`: a clean row beats an error row, the last clean row wins, and the two chains, which share `run_id` values, are told apart by `engine_backend`. Keying on `run_id` alone kept 186 of 365 rows in the landing rehearsal | before landing the four-arm rows | [test_merge_fourarm_rows.py](test_merge_fourarm_rows.py) | land from the file: `BENCH_LAND_PULLED_FILE=FILE python land_stage.py ...` (PUBLISHING.md). The host, the four remote directories and the results directory are environment variables, listed in the docstring |
| [rows_audit.py](rows_audit.py) | clean reps per ArcadeDB cell and client series (embedded, lean HTTP, official driver, PostgreSQL wire), counted from the rows. The rep-state files do not name the client, and a union of the main and the `-pgwire` files counted PostgreSQL-wire reps as HTTP reps, which hid seven served cells with one HTTP rep | after the catch-up stages, before saying n=3 | [test_rows_audit.py](test_rows_audit.py) | rerun the series it lists below three clean reps, or say why they are absent |
| [rep_state_audit.sh](rep_state_audit.sh) | the cells of the paper pins with fewer than N ok reps in the rep-state files, read together per arm (main, `-pgwire`, strict, and the `-comprerun` file of the comparators). "n=3 done" had been said from a count of ok cells that never listed the cells with no ok rep | on the bench host, `ssh <host> bash -s < experiments/tools/rep_state_audit.sh` | [test_rep_state_audit.py](test_rep_state_audit.py) | rerun the cells it lists. N, the directory and the two pins are environment variables, listed in the script |
